# Цифра — цифровое согласование практик

Реальное веб-приложение на FastAPI + SQLAlchemy + Jinja2, с серверной базой данных, ролевым доступом, защищёнными вложениями, задачами, дедлайнами, журналом событий и одноразовым подключением предприятий.

## Что реально работает

1. Электронная форма создания договора производственной, учебной или преддипломной практики.
2. Приватная загрузка PDF/DOCX/PNG/JPG до 15 МБ; контроль расширения и сигнатуры, SHA-256, версия файла, проверка доступа при скачивании.
3. Сохранение обращений в SQLite (локально) или PostgreSQL (на сервере).
4. Уникальный номер обращения, автоматические временные метки всех этапов.
5. Маршрут по ролям: студент → сотрудник кафедры → ответственный → отдел практик → предприятие; университет/предприятие могут согласовывать в разном порядке (после шага ответственного).
6. Возврат на доработку, повторная загрузка новой версии, история изменений.
7. Отдельные кабинеты для STUDENT, STAFF, COORDINATOR, OFFICE, ENTERPRISE, MANAGER.
8. Одноразовое 48-часовое приглашение предприятия; доступ только к указанному договору.
9. Задачи, ответственные, приоритеты, сроки, статусы, визуализация просрочки.
10. Аналитика «до» по обезличенным 103 записям и «после» по реальным серверным событиям, CSV-экспорт.
11. Инструкция пользователя и расширяемая навигация по будущим модулям.
12. Автоматические тесты доступа и рабочих сценариев.

**Не реализовано:** квалифицированная электронная подпись (УКЭП), интеграция с реальным университетским Directum и корпоративными удостоверяющими центрами, email/SMS, официальная юридическая сила подписания. Кнопки согласования означают **подтверждение этапа внутри прототипа**, не подписание договора в юридическом смысле.

## Локальный запуск

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
cp .env.example .env               # для Windows скопировать вручную
# Отредактировать SECRET_KEY; не сохранять реальные секреты в Git
python -m scripts.seed_demo
uvicorn app.main:app --reload
```

Открыть `http://127.0.0.1:8000`. Временные реквизиты шести тестовых ролей будут в `demo_credentials.txt`. Пароли **случайно генерируются**, не показываются на сайте и не должны быть опубликованы вместе с кодом. Демо-договоры — синтетические. Исходный обезличенный CSV не используется для наполнения личных кабинетов.

## Проверка сценария

- Вход STUDENT → «Новый договор» → черновик → загрузить PDF/DOCX → «Отправить».
- Войти STAFF → открыть договор → «Проверено кафедрой».
- Войти COORDINATOR → одобрить.
- Войти OFFICE/ENTERPRISE в порядке, выбранном при создании → одобрить этапы.
- Руководство/сотрудники → «Журнал событий», «Аналитика», «Задачи».
- Уполномоченный сотрудник → «Предприятия» → создаёт одноразовое приглашение → партнёр активирует собственные логин и пароль.

## Публичный запуск с постоянным хранением на Render

Официальная инструкция находится в [`docs/ПУБЛИКАЦИЯ_НА_RENDER.md`](docs/ПУБЛИКАЦИЯ_НА_RENDER.md).
Подготовлен `render.yaml` с одним платным Render Web Service, приватным **постоянным диском** `/var/data` и приложением FastAPI. SQLite БД и все вложения хранятся на этом диске; содержимое не теряется при обычном редеплое. `SECRET_KEY` создаётся хостингом, `BASE_URL` автоматически берётся у Render. При первом старте безопасный скрипт `scripts/initialize_public.py` создаёт пользователя руководства по реквизитам из секретных переменных `INITIAL_ADMIN_USERNAME` и `INITIAL_ADMIN_PASSWORD` (без публикации пароля), а также один раз загружает 103 обезличенных записи исходных данных. Запуск без администратора прекращается с понятной ошибкой вместо создания публичной учётной записи с известным паролем. После создания администратора пароль и логин из переменных запуска можно удалить.

**Важно:** этот репозиторий **не содержит публичного адреса уже работающего сервиса**. Внешнее развёртывание требует прав владельца хостинга и Git-репозитория, подтверждения параметров и возможных расходов. Сам `render.yaml` не запускает сайт автоматически.

Из локальной демонстрации нельзя переносить в публичный репозиторий `local.sqlite3`, `demo_credentials.txt`, `.env`, `private_uploads/` и пользовательские договоры. Не размещайте реальные документы студентов до утверждения правил доступа и защиты персональных данных. Этапы согласования в MVP не равнозначны юридически значимой электронной подписи.

## Структура

- `app/main.py` — маршруты, валидация действий, журнал, KPI.
- `app/models.py` — БД пользователей, договоров, версий, задач, событий, приглашений, baseline.
- `app/security.py` — Argon2, CSRF, RBAC и разграничение доступа.
- `app/storage.py` — приватные файлы и проверка сигнатуры.
- `templates/`, `static/` — академический интерфейс.
- `scripts/seed_demo.py` — локальная генерация тестовых аккаунтов и примерных документов.
- `scripts/bootstrap_admin.py` — создание руководителя с переданным секретом.
- `data/baseline_103_anonymized.csv` — обезличенная выборка из загруженной таблицы.
- `tests/` — регрессионные проверки.

## Методика сравнения «до / после»

Значение `campus_days` в источнике измеряет полный внутренний цикл; время `submitted_at → completed_at` на сайте измеряет окончание всего маршрута MVP. Для научно корректного сравнения нужны одинаковые границы этапов, одинаковые календарные/рабочие единицы, согласованные когорты и исключение тестовых документов. Дашборд показывает данные раздельно и **не утверждает**, что средний полный цикл сократился на определённый процент.
